# PROJECT CONTEXT: Classifyd (Web3 P2P Marketplace & Crypto Classifieds)

## 1. Концепция и позиционирование
**Classifyd** — некастодиальный P2P-маркетплейс (доска объявлений) для покупки и продажи товаров за криптовалюту (на старте — **USDT**) с использованием смарт-контрактов эскроу и выпуском **NFT-сертификатов сделок** (цифровых чеков/паспортов товара).
* **Юридическая и техническая модель:** Платформа выступает исключительно как поставщик софта (децентрализованный нотариус и витрина). Платформа **не хранит** средства пользователей (non-custodial), не выступает платежным агентом и не требует KYC. Деньги блокируются в автономном смарт-контракте до подтверждения сделки покупателем.
* **Якорная ниша MVP:** Компьютерное железо (видеокарты, ОЗУ, процессоры, майнинг-оборудование) и флагманские смартфоны.
* **Будущие разделы (реализуются как Promo-тизеры / Fake Door с листом ожидания):** Маркетплейс проверенного исходного кода/IT-решений, Pro-аналитика цен, авто-репрайсинг, голосование за добавление новых монет.

---

## 2. Текущий стек и инфраструктура (База уже развернута и очищена)
* **Frontend / BFF:** Nuxt.js (SSR для публичных страниц) + Nitro BFF (единая точка входа для API).
* **Backend:** Python (FastAPI) — полностью изолирован во внутренней Docker-сети (без проброса портов наружу).
* **Cache / Sessions / Rate Limiting:** Dragonfly (Redis-совместимое хранилище).
* **Web Server / Proxy:** Caddy + Cloudflare (WAF, Turnstile, Workers).
* **Контейнеризация:** Docker / Docker Compose.
* **Smart Contracts:** Solidity (EVM-сети: Arbitrum / Polygon / Base).
* **Будущее расширение:** Адаптация фронтенда под Telegram Mini App + Telegram Wallet / TON Connect.

## 3. Архитектурные и сетевые правила (Критически важно)

### 3.1. Изоляция API и защита от парсинга
* **Никаких прямых публичных эндпоинтов FastAPI.** Весь внешний трафик идет только через **Nitro BFF** (например, публичный рут `/api/items/[id]`), который проксирует запросы во внутренний Docker-контейнер FastAPI по обфусцированным внутренним путям (например, `/api/v1/hi/common/...`) с проверкой секретного заголовка `X-Internal-Bff-Secret`.
* **Защита от перебора ID:** В публичных URL и API запрещено использовать автоинкрементные числовые ID. Использовать только `UUIDv7` или `NanoID`.
* **SEO vs Анти-бот:**
  * Публичная витрина (`/`, `/market`, `/market/[id]`) должна работать через **SSR** для индексации Google и AI-поисковиками. На каждой карточке товара генерировать JSON-LD (`Schema.org` -> `Product` + `Offer` с `priceCurrency: "USD"`, состоянием `UsedCondition`/`NewCondition` и блоками `FAQPage`). Запрещено использовать скрытый спам-текст.
  * Контакты продавца не отдаются в исходном HTML — запрашиваются отдельным AJAX-вызовом через Nitro BFF после проверки Cloudflare Turnstile и авторизации.

### 3.2. Авторизация без JWT (Stateful Sessions)
* Авторизация исключительно через подпись криптокошелька (**SIWE — Sign-In with Ethereum**). Никаких логинов, паролей, email или JWT в `localStorage`.
* **Поток входа:** Nuxt запрашивает `nonce` у Nitro -> пользователь подписывает сообщение кошельком -> Nitro проверяет подпись, создает `session_id` в **Dragonfly** (с TTL) и устанавливает клиенту куку `HttpOnly; Secure; SameSite=Strict`.

## 4. Структура интерфейса (3 модуля MVP)
1. **Пояснительный лендинг (`/`):**
   * Главный оффер: P2P-сделки с электроникой за USDT без банковских задержек и комиссий посредников.
   * Интерактивная форма быстрого переноса объявления по ссылке с OLX.
   * Схема работы смарт-контракта в 3 шага, таблица сравнения с классическими досками, тарифная сетка, блок «О нас пишут» (ссылки на внешние IT-статьи) и внутренний раздел `/guides` (`@nuxt/content`).
2. **Публичная витрина (`/market` и `/market/[id]`):**
   * Строгий, плотный каталог (в духе PCPartPicker) с фильтрами по моделям железа, состоянию и цене в USDT.
   * В карточке лота: адрес кошелька продавца, счетчик его NFT-сертификатов сделок, ссылка на видео стресс-теста (FurMark/3DMark), серийный номер и кнопка «Купить через смарт-контракт».
   * Вкладка категории «Код и софт» оформлена как тизер `Coming Soon` с кнопкой записи в `feature_waitlist` (в будущем там будет SAST-аудит архивов через Semgrep/Bandit и проверка пакетов).
3. **Личный кабинет в стиле CRM/ERP (`/dashboard`, отдельный `layout`):**
   * Темная тема (Dark Mode), левый сайдбар, компактные таблицы (`Data Grids`) с массовыми действиями (Bulk Actions).
   * Разделы: Сводка (KPI-карточки), Мои объявления (таблица с быстрым редактированием цен и кнопкой импорта с OLX), Сделки и Эскроу (воронка статусов контрактов), Мои NFT-сертификаты, Промо-закладки разделов «Аналитика [Pro]» и «Репрайсер [Pro]» + виджет голосования за добавление новых криптовалют.

## 5. Ключевые бизнес-механики и монетизация

### 5.1. Тарифная лестница и партнерская программа
* **Free (Базовый):** До **3 активных объявлений** бесплатно. Для защиты от ботов: если у подключенного кошелька 0 транзакций в истории сети (on-chain проверка через RPC с кэшем в Dragonfly), бесплатный лимит недоступен — сразу требуется покупка Паспорта.
* **Seller Passport (Стартовый, \$1 разово):** Покупка Soulbound NFT-паспорта продавца за **1 USDT** открывает лимит до **10 объявлений**, убирает премодерацию и запускает партнерскую выплату: смарт-контракт автоматически переводит **0.50 USDT** пригласившему пользователю (`referrer`) и **0.50 USDT** на кошелек платформы.
* **Business / Pro (Подписка):** От **11+ объявлений**, массовый импорт/экспорт, аналитика и авто-репрайсинг (в MVP реализуется как тизер/лист ожидания).

### 5.2. Импорт лотов с внешних площадок (OLX JSON)
* Парсинг запускается **исключительно по инициативе пользователя** в его кабинете/на лендинге.
* Запрос к публичному JSON внешнего сайта идет через изолированные **Cloudflare Workers** (чтобы не светить IP основного сервера и обходить CORS), результат отдается в Nuxt для мгновенного предпросмотра.
* После нажатия «Опубликовать» FastAPI скачивает изображения на собственное S3/R2 хранилище, удаляет EXIF-метаданные (для анонимности продавца), при необходимости очищает угловой логотип конкурента (OpenCV `inpaint`), накладывает рекламный водяной знак **Classifyd** (с ID лота и статусом эскроу) и сохраняет в WebP.
* Верификация владельца лота: генерация временного кода в Dragonfly, который продавец на 1 минуту добавляет в описание на исходной площадке.

## 6. Логика смарт-контрактов (Solidity)
Контракт должен быть написан с использованием стандартов **OpenZeppelin** (`IERC20`, `ERC721`, `ReentrancyGuard`, `Ownable`) и поддерживать белый список токенов `mapping(address => bool) public allowedTokens` (на старте только USDT, новые добавляются по итогам опросов).
1. **Эскроу сделки (`createDeal`, `confirmDelivery`, `refund`):**
   * Покупатель депонирует сумму в USDT в контракт.
   * После доставки (с учетом тайм-лока на проверку, например 24 часа) покупатель подтверждает получение (или срабатывает таймер), контракт переводит USDT продавцу и **автоматически минтит NFT-сертификат сделки** (с метаданными: хеш транзакции, ID лота, серийник товара).
2. **Продажа Паспорта продавца (`buySellerPassport(address referrer)`):**
   * Принимает 1 USDT, минтит непередаваемый (Soulbound) NFT-паспорт на кошелек покупателя, делит 1 USDT в пропорции 50/50 между `referrer` (если указан валидный адрес) и казначейством платформы.

3. Не предлагай архитектурные решения, нарушающие некастодиальность платформы, анонимность пользователей (никакого KYC/JWT) или раскрывающие внутренние маршруты FastAPI наружу.
4. Приоритет разработки:
   * Шаг 1: Базовый смарт-контракт на Solidity (Escrow + NFT Certificate + Seller Passport) и тесты к нему.
   * Шаг 2: Схема БД (PostgreSQL) и внутренние эндпоинты FastAPI + интеграция с индексатором событий блокчейна.
   * Шаг 3: Nitro BFF (SIWE-авторизация через Dragonfly, проксирование, интеграция с Cloudflare Worker для импорта JSON).
   * Шаг 4: Фронтенд Nuxt (Лендинг, SSR-витрина с JSON-LD и CRM-кабинет с тизерами Pro-функций).
